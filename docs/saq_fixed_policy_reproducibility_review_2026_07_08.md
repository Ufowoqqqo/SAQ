## Artifact Classes

### 1. Build Artifacts

Required binaries:

```text
bin/create_index
bin/compare_search_results
bin/test_qps
```

Producer:

```bash
cmake --build build -j
```

These binaries are required for full safe-search evaluation. A report-only
rebuild does not need them.

### 2. Input Artifacts

The fixed-policy runner does not regenerate dataset/PCA/IVF preparation
artifacts. A clean experiment root must already contain them.

For the applicability scan and abstention decisions:

```text

/tmp/saq-run/data/word2vec_sample100k/word2vec_sample100k_base_pca.vars.fvecs
```

requires the following per dataset/K:


## Reproduction Modes

### Report-Only Reproduction

Use this when summary/applicability CSVs already exist:

```bash
python script/report_fixed_policy_validation.py \
  --root /tmp/saq-run \
  --date 2026_07_08_runner_cost_reduced_eval \
  --summary-csv /tmp/saq-run/reports/fixed_policy_matrix_validation_2026_07_08_runner_cost_reduced_eval.csv \
  --applicability-csv /tmp/saq-run/reports/fixed_policy_applicability_scan_2026_07_08_runner_cost_reduced_eval.csv \
  --output-prefix /tmp/saq-run/reports/fixed_policy_validation_matrix_2026_07_08_runner_cost_reduced_eval \
  --expected-csv docs/saq_fixed_policy_clean_validation_table_2026_07_07.csv \
  --compare-ignore-field source_report
```

This mode does not rerun scoring, indexing, search, or QPS.

### Runner Reproduction With Reuse

Use this when `/tmp/saq-run` already contains many generated artifacts:

```bash
python script/run_fixed_policy_matrix.py \
  --use-cost-reduced-scorer \
  --date 2026_07_08_runner_cost_reduced_eval \
  --artifact-date 2026_07_08_runner_cost_reduced_eval \
  --expected-csv docs/saq_fixed_policy_clean_validation_table_2026_07_07.csv
```

This mode reuses existing candidate/scorer/index/compare/QPS outputs when
their expected paths exist.

### Clean-Root Full Evaluation

A clean root can reproduce the matrix if build and input artifacts are already
available. The same command can be used, but missing runner-generated artifacts
will be recomputed.

To force recomputation of generated artifacts:

```bash
python script/run_fixed_policy_matrix.py \
  --use-cost-reduced-scorer \
  --date <new_date> \
  --artifact-date <new_date> \
  --expected-csv docs/saq_fixed_policy_clean_validation_table_2026_07_07.csv \
  --force \
  --force-build \
  --force-eval
```

This is expensive. It rebuilds custom indexes, reruns safe compare CSVs, and
reruns QPS measurement. It should be used only when a from-scratch evaluation
claim is needed.

## Current Limitations

1. This review proves that the current local root has all enumerated artifacts;
   it does not prove that a new machine already has the required dataset/PCA/IVF
   inputs.
2. The input preparation/verification driver now covers manifest verification
   and command-level preparation for GIST, CIFAR, DEEP, and word2vec. It does
   not cleanly rebuild audio because the exact historical PCA/IVF command was
   not recovered.
3. The source/preparation provenance note now covers GIST, CIFAR, and DEEP at
   command level. Audio and word2vec remain partially reconstructed because the
   current matrix only uses their variance artifacts for abstention.
4. The checker verifies existence for all artifact classes; hash/shape
   provenance is currently limited to the input artifacts enumerated by the
   manifest.
5. Existing QPS CSVs may be reused unless `--force-eval` is supplied. Therefore
   a standard runner reproduction validates the official pipeline and report
   consistency, but not necessarily fresh QPS measurement.
6. `/tmp/saq-run` remains a local artifact root. Durable conclusions must stay
   in checked-in docs and summary tables.

## Practical Conclusion

The current evidence is reproducible at the runner/report level once the build
artifacts and dataset/PCA/IVF inputs are present. The input manifest makes the
current prepared inputs checkable by full-file SHA256, the provenance note
documents the command-level preparation chain for the evaluated GIST, CIFAR,
and DEEP rows, and `script/prepare_fixed_policy_inputs.py` turns that chain into
an executable verification/preparation interface. The remaining clean-machine
gap is testing the driver on a fresh root and resolving or archiving exact audio
preprocessing if audio ever becomes an evaluated row.

The next reproducibility improvement should therefore be either:

```text
test the preparation driver on a fresh experiment root, or archive the input
bundle with manifest hashes
```

Further plan tuning should wait until this provenance gap is acceptable for the
intended meeting or paper narrative.
