# Source-Aligned SymphonyQG Scalar Estimator

## Scope

This note records the scalar milestone of Phase 2. The objective is baseline
correctness: reproduce SymphonyQG's transformed vertex-residual estimator before
using it to evaluate any SAQ-specific graph hypothesis. This implementation is
not a new research method and does not yet reproduce packed FastScan or graph
traversal.

The pinned reference is SymphonyQG revision:

```text
6124ddb34ee4d176edea1bd7ad38d1672343df28
```

The source-aligned behavior was derived from:


## Estimator Definition

Let the original dimension be `D` and let

```text
Dp = 2^ceil(log2(D)).
```

SymphonyQG pads each vector to `Dp`, samples a shared sign vector
`a in {-1,+1}^Dp`, and applies an unnormalized Fast Hadamard Transform:

```text
x_tilde = H * diag(a / sqrt(Dp)) * [x; 0].
```

The local deterministic variant uses an explicit `uint64_t` seed, the same
`mt19937_64` engine, and the same `uniform_int_distribution<int>(0,1)` as the
official `FHTRotator`. The official constructor starts from `random_device` and
serializes the sampled matrix; the local diagnostic records the seed in every
aggregate output.

For a transformed query `q_tilde`, define a range that includes zero:

```text
lo = min(0, min_j q_tilde_j)
hi = max(0, max_j q_tilde_j)
width = (hi - lo) / (2^6 - 1)
c_j = lround((q_tilde_j - lo) / width + 0.5)
sumq = sum_j c_j.
```

For a directed edge from current vertex `u` to neighbor `v`, let

```text
r = v_tilde - u_tilde
s_j = +1 if r_j > 0, otherwise -1
z = 1 / sqrt(Dp)
f0 = <r, s> * z / ||r||_2
f1 = <u_tilde, s> * z
alpha = ||r||_2 / f0.
```

The three per-edge factors are

```text
triple_x = ||r||_2^2 + 2 * alpha * f1
factor_dq = -2 * alpha * z
factor_vq = factor_dq * sum_j s_j.
```

The scalar equivalent of the packed FastScan dot product is

```text
signed_dot = sum_j s_j * c_j
           = 2 * sum_{j:s_j=+1} c_j - sumq.
```

Given the exact current-vertex distance `d(q,u)`, the estimated neighbor
distance is

```text
d_hat(q,v | u) = d(q,u)
               + triple_x
               + factor_vq * lo
               + factor_dq * width * signed_dot.
```

No additional non-negative clamp is applied. For a fixed query-root event,
`d(q,u)` is common to every neighbor, so its floating-point reduction order does
not affect neighbor ordering.

The official factor formula is undefined for a zero residual (`v=u`) because
both the residual norm and `f0` are zero. The diagnostic defines this degenerate
case explicitly as `d_hat(q,v|u)=d(q,u)`, which is exact for duplicate vectors,
and records the number of such edges in its output.

## Implementation

The scalar implementation is in:

```text
saqlib/baseline/symphonyqg_scalar.hpp
```

The local replay integration is in:

```text
src/profile_graph_frontier.cpp
```

The profiler now:

1. rotates each subset data vector once;
2. encodes each fixed-adjacency edge once, as index-build state;
3. prepares one rotated 6-bit query representation per held-out query;
4. evaluates each root-neighbor edge with its stored residual code and factors;
5. reports `symqg_fht_scalar` separately from the historical unrotated
   `symqg_vertex_proxy`;
6. records source revision, original and padded dimensions, rotation seed, and
   scalar evaluation path.

The reported `code_bits_only` value is `Dp`, one residual-sign bit per padded
coordinate. It excludes the three stored float factors, graph adjacency, query
LUT, and implementation-dependent alignment.

## Official-Source Parity Fixture

The fixture uses `D=63`, `Dp=64`, seed `7`, one current vertex, and 16
neighbors. The last two neighbors are identical, which verifies deterministic
tie ordering by neighbor id. Input values are generated by
`unit_test/fixtures/symphonyqg_scalar_fixture_input.hpp`.

The official-source generator is:

```text
script/reference/symphonyqg_scalar_fixture_generator.cpp
```

It compiles directly against the pinned SymphonyQG headers and writes expected
values for:

- signs and rotated vectors;
- query range, width, codes, and code sum;
- every residual sign bit;
- `triple_x`, `factor_dq`, and `factor_vq`;
- signed query-code dots;
- every estimated distance;
- final ordering, including the tied pair.

SymphonyQG's production build uses `-Ofast`. Its query maximum is on an
`lround` boundary, so production fast-math and strict Debug arithmetic can
legitimately differ by one query-code unit. Two references are therefore
generated from the same official source: a production `-Ofast` fixture and a
strict-fp fixture. The test selects the reference matching its build mode; this
does not alter the production replay semantics.

## Complexity

For `N` indexed vectors, `E` directed graph edges, and padded dimension `Dp`:

| operation | time | additional logical storage |
|---|---:|---:|
| rotate all indexed vectors | `O(N Dp log Dp)` | `O(N Dp)` if retained during construction |
| encode all edge signs and factors | `O(E Dp)` | `E * (Dp bits + 3 floats)` |
| prepare one query | `O(Dp log Dp + Dp)` | `O(Dp)` |
| one scalar edge estimate | `O(Dp)` | `O(1)` temporary beyond the query and edge code |

The scalar path is a semantic reference, not a runtime baseline. The official
packed path replaces the `O(Dp)` scalar signed dot with FastScan block
operations; that path remains the second Phase 2 milestone.

vectors, and independent local events. It does not execute beam traversal,
SymphonyQG multiple estimates, or packed FastScan, and it does not provide a
runtime comparison.

## Phase Decision

The source-aligned scalar milestone is complete. It corrects the baseline
semantics and confirms that the old proxy was not adequate. Full Phase 2 remains
open until a packed/FastScan-equivalent path matches scalar rank ordering on the
parity cases. No SAQ-specific graph method should be designed before that
remaining baseline step and the subsequent Phase 3 stop gate.
