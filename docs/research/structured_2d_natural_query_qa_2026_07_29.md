# Structured-2D natural-query one-page Q&A

## 30 秒总结

**完整查询实验的终局是 NO-GO，但存在局部正结果。** 94 个逻辑配置、
1,316 个正式 pass 全部完成且结果稳定。32 B 在 SIFT 上失败；64 B 只在
`SIFT/nlist=4096` 的高候选区域通过，在 `nlist=1024` 不通过。GIST 的
`nlist=1024` 通过，但 `nlist=4096` 因完整索引更大而失败。因此没有一个
预算能同时通过两个数据集和两种索引规模。

## 最可能的问题

**“共享二维形状”到底共享了什么？**

所有 64 个坐标对共用同一组二维参考点和同一套标签。每个坐标对只保存
一个二维平移和一个 `2×2` 变换，把参考点拉伸、旋转或倾斜到自己的
位置。数据库仍然只为每对坐标存一个 4-bit 或 8-bit 标签。

**为什么查询时还要为每个粗单元重新建表？**

编码对象是“数据库向量减去所属粗单元中心”的残差。查询与不同粗单元
比较时，查询残差也不同，所以 64 张距离表必须按粗单元重建。扫描一个
单元内的每个候选只做 64 次查表和加法；该单元候选越多，建表成本越
容易摊平。

**这是不是说明 Attempt 4 完全没有价值？**

不是。`SIFT/4096/64 B` 有真实的端到端正点：Recall 约 0.926、吞吐量约
966 QPS，比匹配 Recall 的 OPQ 快约 56%。问题是它没有跨设置复现。

**为什么一个点赢了还要判失败？**

因为检索系统很容易在一个数据集、一个索引大小或一个搜索深度上偶然
占优。事先规定的贡献条件要求同一预算在两个数据集和两种索引规模都
通过，避免看完结果后挑最好看的点。

**Recall 0.002 的提高有多大？**

它表示每个查询平均多找回约 0.2 个真实前 100 邻居。门槛不大，但必须
在近似相同吞吐量、完整索引不更大、构建成本可接受的情况下达到。

**为什么 64 B、4,096 cells 有效，1,024 cells 无效？**

当前证据说明更高容量改善了距离排序，而较高候选量能摊平每个单元的
距离表构造成本。但实验没有把“容量”和“候选量”的机制完全分开，因此
这只能作为后续诊断问题，不能事后改模型救当前结论。

**32 B 为什么失败得更明显？**

共享形状在低容量时约束太强，SIFT 上的 Recall 低于强 PQ/OPQ 基线；
同时表构造成本仍然存在，所以质量和速度都没有形成交换优势。

**GIST 为什么看起来很好？**

GIST 的 960 维中只有前 128 维按向量编码，其余 832 维使用粗单元中心
近似。这个固定设计有时给出很快的查询，但搜索更多单元也会引入尾部
近似造成的假阳性。因此 GIST 是有效系统结果，却不是纯粹的二维形状
归因实验。

**GIST/4096 速度很好，为什么被 bytes 拒绝？**

S 必须携带外部全维粗索引才能完成路由和尾部定义。4,096 个单元时，这
部分状态使完整序列化索引超过匹配基线。协议比较完整可用系统，不只
比较每向量标签。

**这个 byte 失败是不是纯工程问题？**

部分是容器和状态所有权问题，但不是终局失败的唯一原因。即使重新设计
GIST 的存储，SIFT 的三组失败仍然阻止当前共同贡献。

**是不是基线用了更少工作？**

不是。所有方法都重新执行相同 PCA、粗单元选择和 top-100；完整表构造、
扫描和结果维护都在计时内。所有方法使用相同候选列表。

**多线程比较公平吗？**

是。吞吐量统一使用 12 个物理核心，线性代数内部固定单线程，QPS 直接
用完整 query batch 的 wall time计算。单查询延迟另用一个线程测量。

**为什么 GIST Recall 随搜索单元增加可能下降？**

更多单元不只带来更多真实候选，也带来更多使用不同尾部中心近似的
候选。一些候选的近似尾部距离会过小，从而把真正邻居挤出前 100。这
不是 Recall 计算错误，IVF-Flat 和全维 PQ 对照已经排除了通用路由问题。

**可以只发表 SIFT/4096/64 B 吗？**

证据不足。严格 reviewer 会问为什么相邻预算、另一索引大小和另一
数据集不能复现。除非找到一个事前可定义、与数据库机制有关的适用条件，
否则只是局部 operating point。

**下一步最有价值的问题是什么？**

诊断高容量、高候选量正区域的机制：收益究竟来自 shared shape 的排序
能力、表成本摊销，还是两者共同作用。任何新方法都应先冻结机制假设，
不能用这次 query 结果挑规则或阈值。

## 需要记住的数字

- 完整矩阵：94 个逻辑配置，188 warmup，1,316 measured pass。
- 资源：239.25 CPU-hours，101.22 wall-hours，峰值 11.12 GiB。
- 最清楚正点：SIFT/4096/64 B，`nprobe=256`，Recall `0.926075`，
  `966 QPS`。
- 对匹配 Recall OPQ：约 `+56% QPS`、`-29% p95 latency`。
- SIFT/1024/64 B：约 `-11% QPS`，Recall 差 `-0.000413`。

## 避免这些说法

- 不说“S 在 GIST 和 SIFT 都赢了”；说“只有部分 setting 通过”。
- 不说“GIST 证明 shared shape 更好”；说“GIST 含固定尾部近似影响”。
- 不说“实现完成就是贡献”；说“实现使终局判定可信”。
- 不说“所有二维结构都失败”；说“当前共享形状和固定规则不够稳健”。
- 不说“再调一下 `nprobe` 就行”；所有 `nprobe` 已事先固定并全部报告。
